# โครงสร้างฐานข้อมูล Google Sheets

เรียก `setupSystem()` จาก Apps Script editor ด้วยบัญชีเจ้าของโครงการเพื่อสร้างชีตด้านล่างใน [Google Sheet ที่กำหนด](https://docs.google.com/spreadsheets/d/1nqfPAnIifkQV3NrD045__PNK7qe3n-cxBcdeqvfBwUw/edit) การสร้างชีตจริงต้องผ่านสิทธิ์ Google ไม่เกิดขึ้นจากการเปิดหน้า GitHub Pages

แถว 1 เป็นหัวคอลัมน์ภาษาอังกฤษ ใช้ลำดับตรงตาม `SHEET_SCHEMAS` ใน `apps-script/Config.gs` ระบบตรวจหัวคอลัมน์ก่อนอ่านเขียน และไม่เขียนทับชีตเดิมที่โครงสร้างไม่ตรง เรียก setup ซ้ำได้โดยไม่ลบข้อมูลเดิม แม่แบบหัวคอลัมน์ที่ไม่มีข้อมูลส่วนตัวอยู่ใน [sheet-headers.json](sheet-headers.json)

## ชีตที่สร้าง

| ชีต | ใช้เก็บ |
| --- | --- |
| `students` | นักเรียนและห้องปัจจุบัน |
| `classrooms` | ห้องเรียนและครูที่ปรึกษา |
| `users` | บัญชีผู้ดูแล/ครู พร้อมข้อมูลตรวจรหัสผ่าน |
| `attendance` | สถานะนักเรียนในวันและห้องที่เช็คชื่อ พร้อมพิกัด |
| `attendance_batches` | เวอร์ชันชุดเช็คชื่อรายห้อง/วัน เพื่อตรวจการแก้ข้อมูลพร้อมกัน |
| `settings` | ข้อมูลโรงเรียนและค่าที่ไม่ใช่ความลับ |
| `logs` | ประวัติการใช้งานและการแก้ไข ก่อน/หลัง |
| `sessions` | ค่า hash ของ session และเวลาใช้งาน |
| `mutations` | รหัสคำขอบันทึก เพื่อหลีกเลี่ยงบันทึกคำขอเดิมซ้ำ |

ไม่มีรายชื่อนักเรียนหรือครูตัวอย่างถูกเพิ่มโดย `setupSystem()` บัญชี `admin` ใช้รหัสผ่านสุ่มชั่วคราวที่แจ้งใน Execution log แล้วบังคับเปลี่ยนเมื่อเข้าสู่ระบบ

## `students`

```text
studentId,prefix,firstName,lastName,classroomId,number,active,createdAt,updatedAt
```

`studentId` เป็นเลขประจำตัวนักเรียนที่ไม่ซ้ำ รักษาเป็นข้อความเพื่อเก็บศูนย์นำหน้า `classroomId` อ้างถึง `classrooms.classroomId` และ `number` คือเลขที่ในห้อง `active` แสดงว่ายังใช้งานอยู่ การย้ายนักเรียนไม่เปลี่ยนห้องที่บันทึกไว้ในประวัติเช็คชื่อเดิม

## `classrooms`

```text
classroomId,name,level,advisorId,active,createdAt,updatedAt
```

`classroomId` เป็นรหัสห้องที่ไม่ซ้ำ `name` เป็นชื่อที่แสดง เช่นระดับและห้อง `advisorId` อ้างถึง `users.userId` ของครูที่ปรึกษา backend ให้สิทธิ์เมื่อเป็นครูที่ปรึกษาของห้อง หรือมีห้องอยู่ใน `users.classroomIds` อย่าแก้เฉพาะชื่อที่แสดงเพื่อเปลี่ยนสิทธิ์

## `users`

```text
userId,username,displayName,role,classroomIds,active,mustChangePassword,passwordSalt,passwordHash,passwordIterations,createdAt,updatedAt
```

`role` ใช้ `admin` หรือ `advisor` และ `classroomIds` เป็นรายการรหัสห้องในรูป JSON เช่น `[]` บัญชีครูควรผูกเฉพาะห้องที่ได้รับมอบหมาย `mustChangePassword` ระบุว่าต้องเปลี่ยนรหัสผ่านก่อนทำงานอื่น

รหัสผ่านที่สร้างใหม่ เปลี่ยน หรือรีเซ็ต เก็บเป็นข้อความอ่านได้ในคอลัมน์ `password` ของชีต `users` ตามการตั้งค่าของโรงเรียน รหัสผ่านใหม่อย่างน้อย 8 ตัว ใช้ตัวเลขล้วนได้ บัญชีเดิมยังตรวจสอบ PBKDF2-SHA256 ได้จนกว่าจะเปลี่ยนรหัสผ่าน (แฮชเดิมย้อนกลับเป็นรหัสผ่านไม่ได้) frontend และ logs ไม่ได้รับรหัสผ่าน ผู้ที่ดูชีตได้จะเห็นรหัสผ่านใหม่ได้ ผู้ที่แก้ไข Sheet หรือ Apps Script ได้ถือเป็นผู้ดูแลข้อมูลที่มีสิทธิ์สูง จึงต้องจำกัดการแชร์ไฟล์ด้วย

## `attendance`

```text
attendanceId,date,classroomId,studentId,status,reason,latitude,longitude,accuracy,capturedAt,locationError,updatedBy,updatedAt
```

| คอลัมน์ | ความหมาย |
| --- | --- |
| `attendanceId` | รหัสรายการที่คงเดิมเมื่ออัปเดต |
| `date` | วันที่เช็คชื่อ รูปแบบ `YYYY-MM-DD` |
| `classroomId`, `studentId` | ห้อง ณ วันที่เช็คชื่อและเลขประจำตัวนักเรียน |
| `status` | `present` = มา, `absent` = ขาด, `late` = สาย, `leave` = ลา |
| `reason` | เหตุผลรายบุคคล |
| `latitude`, `longitude` | พิกัดจากอุปกรณ์ของผู้บันทึก |
| `accuracy` | ค่าความคลาดเคลื่อนเป็นเมตรที่เบราว์เซอร์รายงาน |
| `capturedAt` | เวลาที่อุปกรณ์จับพิกัด |
| `locationError` | เหตุที่ไม่มีพิกัด เช่นไม่อนุญาตหรือ timeout |
| `updatedBy`, `updatedAt` | ผู้บันทึกและเวลาอัปเดตล่าสุด |

รายการเดิมของวัน/นักเรียนจะถูกอัปเดตแทนเพิ่มแถวซ้ำ การล้างข้อมูลคือยกเลิกสถานะที่เช็คไว้ ให้ตรวจคำยืนยันและบันทึกประวัติเดิมใน `logs` การยังไม่เช็คชื่อไม่ใช่สถานะขาด

พิกัดใช้ประกอบการตรวจย้อนหลัง เบราว์เซอร์อาจให้ข้อมูลคลาดเคลื่อน และผู้ใช้ปฏิเสธสิทธิ์ได้ หากไม่มีพิกัดต้องเก็บเหตุ ไม่สร้างละติจูด/ลองจิจูดสมมุติ ระบบตรวจช่วงพิกัดและเวลาจับพิกัดก่อนบันทึก

## `attendance_batches`

```text
batchId,date,classroomId,revision,updatedAt,updatedBy
```

ระบุ revision ล่าสุดของชุดเช็คชื่อรายวัน/ห้อง เมื่อครูสองคนแก้ข้อมูลเดียวกัน backend ใช้ revision เพื่อตรวจการทับข้อมูลเก่า ผู้ใช้ต้องโหลดข้อมูลล่าสุดและตรวจรายการก่อนส่งใหม่เมื่อมีข้อขัดแย้ง

## `settings`

```text
key,value,updatedAt,updatedBy
```

`value` เก็บ JSON ของค่า เช่น string, boolean หรือรายการผู้บริหาร ค่าที่สร้างเริ่มต้นประกอบด้วย:

- ข้อมูลโรงเรียน: `schoolName`, `affiliation`, `address`, `email`, `website`, `logoUrl`

ชีต `user_emails` เก็บอีเมลรีเซ็ตรหัสผ่านแยกจากชีต `users` และชีต `password_resets` เก็บแฮชของโทเคนที่หมดอายุภายใน 15 นาทีและใช้ครั้งเดียว ระบบไม่เก็บโทเคนจริงลง Google Sheet
- ผู้บริหาร: `director`, `deputyDirectors` ไม่เกินสามคน
- ธีม: `primaryColor`, `secondaryColor`
- รายงาน: `reportTime` รูปแบบ `HH:mm`, `dailyReportEnabled`
- LINE: `lineEnabled`, `lineTargetId`
- Telegram: `telegramEnabled`, `telegramChatId`
- Chatbot: `chatbotEnabled`, `chatbotUrl`

token ของทุกช่องทางเก็บใน **Script Properties** ของ Apps Script ผ่าน API ตั้งค่า ไม่เก็บใน `settings`, frontend หรือ repository การอ่านค่าทั่วไปคืนเพียงสถานะว่ากำหนดความลับแล้ว ค่าเปิดการแจ้งเตือนทั้งหมดเริ่มเป็น `false`

## `logs`

```text
logId,timestamp,actorId,actorName,action,entityId,beforeJson,afterJson,locationJson,requestId
```

บันทึกเวลา ผู้กระทำ ประเภทการทำงาน เป้าหมาย ข้อมูลก่อน/หลัง และพิกัดประกอบ สำหรับตรวจย้อนหลัง ข้อมูล JSON ไม่รวมรหัสผ่านหรือ token เก็บเป็นค่าอ่านย้อนหลังไม่ใช่สูตร Sheet

ประวัติใน Sheet ไม่ใช่หลักฐานที่ป้องกันการแก้ไขโดยเจ้าของไฟล์ ผู้มีสิทธิ์แก้ไขไฟล์ Google ยังแก้แถวได้ ควรจำกัดผู้แก้ไขและสำรองข้อมูลตามรอบที่โรงเรียนกำหนด

## `sessions`

```text
tokenHash,userId,expiresAt,createdAt,revokedAt
```

เก็บค่า hash ของ session token ไม่ใช่ token ที่เบราว์เซอร์ใช้ บัญชีที่ถูกปิดใช้งานหรือ session ที่หมดอายุ/ถูกยกเลิกต้องเข้าสู่ระบบใหม่ ระยะเวลาเริ่มต้นของ session คือ 12 ชั่วโมงตาม `APP_CONFIG`

## `mutations`

```text
mutationId,userId,action,payloadHash,resultJson,createdAt
```

เก็บรหัสคำขอและผลลัพธ์เพื่อให้การลองส่งซ้ำหลังเครือข่ายหลุดไม่สร้างรายการซ้ำ รหัสเดิมต้องมี payload เดิม หากเปลี่ยนรายละเอียดให้สร้างคำขอใหม่

## วันที่ สถิติ และความถูกต้อง

วันที่ใช้ปีคริสต์ศักราช `YYYY-MM-DD` และเวลาใช้ ISO timestamp การแสดงผลสำหรับผู้ใช้อ้าง timezone `Asia/Bangkok` อย่าใช้ปีพุทธศักราชในคอลัมน์ `date`

สถิติแยกสถานะทั้งสี่และจำนวนที่ยังไม่เช็คไว้ชัดเจน การสรุปหลายวันนับจำนวนรายการนักเรียนต่อวัน ไม่ใช่จำนวนคนที่ไม่ซ้ำทั้งช่วง รายงานต้องแสดงช่วงเวลาและตัวกรองเพื่อให้ตรวจเทียบข้อมูลได้

อัตรามาเรียนคำนวณ `(มา + สาย) ÷ จำนวนรายการที่ควรเช็คชื่อ × 100` ฐานจำนวนที่ควรเช็คใช้รายชื่อนักเรียนปัจจุบันที่เปิดใช้งานและถูกสร้างแล้ว ณ วันนั้น รวมรหัสนักเรียนที่มีรายการย้อนหลังในห้องนั้นอยู่ ไม่ได้เก็บประวัติทะเบียนนักเรียนแยกตามภาคเรียน

รายงานหลายวันหรือรายเดือนนับเฉพาะวันที่มีการบันทึกเช็คชื่อในห้องที่ผู้ใช้เข้าถึงและเลือกไว้ รวมวันที่เคยบันทึกแล้วล้างข้อมูล รายงานวันเดียวแสดงนักเรียนที่ยังไม่เช็คด้วย หากช่วงวันที่ไม่มีบันทึกเลยจะแสดงจำนวนและอัตราเป็นศูนย์ ยังไม่มีปฏิทินวันเรียนและประวัติทะเบียนแยกภาคเรียน จึงควรตรวจความครบถ้วนก่อนใช้เป็นสถิติทางการ ช่วงรายงานสูงสุด 366 วัน และ PDF รองรับรายละเอียดไม่เกิน 5,000 รายการต่อครั้ง

สำรอง Sheet และ PDF ก่อนเปลี่ยน schema หลีกเลี่ยงแก้ข้อมูลบัญชี/หัวคอลัมน์ด้วยมือระหว่างเปิดระบบ การแก้ผ่านเว็บมี validation, การตรวจสิทธิ์ และประวัติการแก้ไข
