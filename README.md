# ระบบเช็คชื่อออนไลน์ โรงเรียนตากใบ

Web App สำหรับเช็คชื่อภาคสนามผ่านโทรศัพท์มือถือ ใช้ HTML, JavaScript แบบ OOP และ SweetAlert2 โดย GitHub Pages เป็น frontend, Google Apps Script เป็น backend และ Google Sheets เป็นฐานข้อมูล

ปรับปรุงเอกสารล่าสุด: **2 ตุลาคม 2569**

## การคำนวณสถิติ

ค่าน้ำหนักเริ่มต้นปรับได้ใน **ตั้งค่า** และบันทึกในชีต `settings`:

| สถานะ | น้ำหนัก |
| --- | ---: |
| มา | 1 |
| ขาด | 0 |
| ลา | 0.5 |
| สาย | 0.25 |

```text
อัตรามาเรียน (%) =
  [(มา × น้ำหนักมา) + (ขาด × น้ำหนักขาด)
   + (ลา × น้ำหนักลา) + (สาย × น้ำหนักสาย)]
  ÷ จำนวนรายการที่ควรเช็คชื่อ × 100
```

รายการที่ยังไม่เช็คแสดงแยกจากขาด กราฟแท่งแสดงจำนวนคนตามสถานะ ส่วนเส้นแสดงร้อยละตามน้ำหนักที่ตั้งไว้ สถิติรายวันและรายเดือนเป็นจำนวนรายการนักเรียนต่อวัน ไม่ใช่จำนวนคนที่ไม่ซ้ำทั้งช่วง รายงานหลายวันนับเฉพาะวันที่มีการบันทึกเช็คชื่อ

## รหัสผ่านและการรีเซ็ต

- รหัสผ่านใหม่ยาว **8–128 ตัว** ใช้ตัวเลขล้วนได้ ไม่บังคับตัวพิมพ์ใหญ่หรือตัวอักษรพิเศษ
- บัญชีที่ใช้รหัสผ่านชั่วคราวต้องเปลี่ยนรหัสผ่านก่อนใช้งาน
- รหัสผ่านที่สร้างใหม่ เปลี่ยน หรือรีเซ็ต เก็บเป็นข้อความอ่านได้ในคอลัมน์ `password` ของชีต `users` ตามการตั้งค่าปัจจุบันของโครงการ ผู้ที่ดูชีตได้จึงอ่านรหัสผ่านเหล่านี้ได้
- บัญชีเดิมที่เก็บ PBKDF2 ยังเข้าสู่ระบบได้ จนกว่าจะเปลี่ยนหรือรีเซ็ต แฮชเดิมแปลงกลับเป็นรหัสผ่านไม่ได้
- ระบบไม่ส่งรหัสผ่านกลับมากับรายการผู้ใช้ และไม่บันทึกรหัสผ่านใน `logs` ส่วน session token และ reset token ยังเก็บเป็นค่าแฮช
- ผู้ดูแลกด **รีเซ็ตรหัสผ่าน** ข้างบัญชีในเมนู **ครูและบุคลากร** ได้ทุกบัญชี ระบบกำหนดรหัสผ่านชั่วคราว บังคับเปลี่ยนเมื่อเข้าสู่ระบบครั้งถัดไป และยกเลิกเซสชันกับลิงก์รีเซ็ตเดิม โดยไม่เปลี่ยนสิทธิ์หรือสถานะบัญชี
- การขอรีเซ็ตต้องระบุ **ชื่อผู้ใช้และอีเมลที่ลงทะเบียนตรงกันทั้งสองอย่าง** ถ้าไม่ตรงกันแสดง “ไม่พบชื่อผู้ใช้และอีเมลที่ระบุ” และให้กรอกใหม่ ถ้าตรงกันส่งลิงก์ผ่านอีเมล ลิงก์ใช้ครั้งเดียวและหมดอายุ **15 นาที**

ไม่มีรหัสผ่านผู้ดูแลตายตัวใน README หรือ repository การติดตั้งใหม่ใช้ `setupSystem()` สร้างบัญชี `admin` พร้อมรหัสผ่านสุ่มชั่วคราวใน Execution log ของเจ้าของโครงการ หากมีชื่อบัญชีเดิมอยู่ ระบบอาจสร้างชื่อ `admin.<รหัส>` แทนและแจ้งใน log

## ติดตั้งและอัปเดต

1. ใช้บัญชีเจ้าของที่แก้ไข Sheet และโครงการ Apps Script ได้ ตรวจ ID ฐานข้อมูลและโฟลเดอร์ใน `apps-script/Config.gs`
2. ติดตั้งไฟล์ `.gs`, `Bridge.html` และ `appsscript.json` จาก `apps-script/` หรือเรียก `npm run bundle` แล้วใช้ไฟล์รวมจาก `artifacts/` **เลือกแบบแยกไฟล์หรือแบบรวมอย่างใดอย่างหนึ่ง** เพื่อไม่ประกาศคลาสซ้ำ
3. ตั้งฐานข้อมูลเป็น Restricted ตามค่าเริ่มต้น หากเลือกใช้ชีตที่แชร์สาธารณะ/ทั้งองค์กร ต้องยืนยันที่ **Apps Script → Project Settings → Script Properties** ด้วยชื่อ `ALLOW_PUBLIC_DATABASE` และค่า `true` การตั้งค่านี้ไม่เปลี่ยนสิทธิ์แชร์ไฟล์ให้เอง โฟลเดอร์ PDF ยังต้องเป็น Restricted
4. เรียก `setupSystem()` จาก Apps Script Editor ด้วยบัญชีเจ้าของ เพื่อสร้างชีตและบัญชีเริ่มต้น ระบบรักษาข้อมูลเดิมไว้และไม่เพิ่มนักเรียนตัวอย่าง
5. เผยแพร่ Web App แบบ **Execute as: Me / Who has access: Anyone** แล้วใส่ URL `/exec` ใน `config.js`
6. เปิด GitHub Pages แบบ **GitHub Actions** แล้ว push branch `main` Workflow ตรวจโค้ดและทดสอบก่อนเผยแพร่เฉพาะ frontend
7. เข้าสู่ระบบ เปลี่ยนรหัสผ่านชั่วคราว ตั้งอีเมลบัญชีครู สร้างห้องเรียน กำหนดครูที่ปรึกษา และนำเข้านักเรียน

เมื่อแก้ backend ต้องอัปเดต source และเลือก **Deploy → Manage deployments → Edit → New version → Deploy** การ push GitHub อย่างเดียวไม่อัปเดต Apps Script เมื่ออัปเดต schema ระบบเพิ่มคอลัมน์ `users.password` สำหรับโครงสร้างเดิมที่รองรับโดยไม่ลบรหัสผ่านเดิม

ฐานข้อมูลมี `students`, `classrooms`, `users`, `attendance`, `attendance_batches`, `settings`, `logs`, `sessions`, `mutations`, `user_emails`, `password_resets` และ `public_stats` ส่วน `staff_directory` เป็นตารางเสริมจากฟังก์ชันจัดเตรียมบุคลากร ภาพรวมสาธารณะใช้ข้อมูลรวมจาก `public_stats` และสามารถแสดงจำนวนนักเรียนที่เปิดใช้งานในวันปัจจุบันก่อนเริ่มเช็คชื่อได้

อ่าน [คู่มือติดตั้ง](docs/DEPLOYMENT.md), [โครงสร้างฐานข้อมูล](docs/DATABASE.md) และ [คู่มือผู้ใช้](docs/USER_GUIDE.md)

## พัฒนาและตรวจสอบในเครื่อง

ต้องมี Node.js สำหรับคำสั่งต่อไปนี้:

```powershell
npm start       # เปิด HTTP server ที่ http://127.0.0.1:4173
npm run check   # ตรวจ syntax frontend และ Apps Script
npm test        # ทดสอบ frontend และ backend จำลองบริการ Google
npm run bundle  # สร้างชุดติดตั้ง Apps Script ใน artifacts/
```

โหมดทดลองใช้ข้อมูลสมมุติในหน่วยความจำ ไม่เขียนลง Google Sheet และส่งออก PDF ผ่านหน้าต่างพิมพ์ การทดสอบในเครื่องไม่แทนการตรวจ deployment, สิทธิ์ Google, อีเมล, พิกัด และ PDF จริง

```text
index.html                  หน้าเริ่มต้น
config.js                   URL backend สาธารณะ
assets/app.js               ควบคุมการทำงาน โหลดข้อมูล และคิวบันทึก
assets/api.js               เชื่อม Apps Script และโหมดข้อมูลตัวอย่าง
assets/views.js             หน้าและแบบฟอร์ม
assets/charts.js            กราฟแท่งและเส้นแบบ SVG
assets/core.js              ฟังก์ชันร่วมและ DraftQueue
assets/manual.js             คู่มือบนเว็บ
apps-script/                บริการ OOP, bridge, schema และ manifest
apps-script/tests/          ทดสอบ backend ด้วยบริการ Google จำลอง
tests/                      ทดสอบ frontend
scripts/                    ตรวจโค้ด สร้าง bundle และเครื่องมือเผยแพร่
docs/                       คู่มือผู้ใช้ ติดตั้ง และฐานข้อมูล
.github/workflows/pages.yml ตรวจสอบและเผยแพร่ GitHub Pages
```

## การโหลดข้อมูลและการใช้งานภาคสนาม

- ใช้ cache ระยะสั้น 10–30 วินาทีและรวมคำขอที่กำลังโหลดซ้ำ การบันทึกเช็คชื่อล้างเฉพาะ cache สถิติที่เกี่ยวข้อง
- แนวโน้ม 7 วันส่งมาพร้อมคำขอ dashboard เดิม กราฟใช้ SVG ไม่โหลดไลบรารีกราฟเพิ่มเติม
- การโหลดหน้ารายงานแสดงแถบสถานะ SweetAlert แสดงสถานะสำคัญกลางจอและอัปเดตความคืบหน้าใน popup เดิม
- เริ่มขอพิกัดเมื่อเปิดเว็บ โดยผู้ใช้ต้องอนุญาตตำแหน่ง แผนที่ดาวเทียมแสดงบนหน้าเข้าสู่ระบบ รายการเช็คชื่อเก็บพิกัด ความแม่นยำ และเหตุที่รับพิกัดไม่ได้
- รายการรอบันทึกเก็บในอุปกรณ์เดิมและแยกตามบัญชี `mutationId` ป้องกันการเขียนซ้ำเมื่อส่งคำขอเดิมอีกครั้ง รายการค้างเกิน 24 ชั่วโมงถูกล้างเมื่อกู้คืนคิว ต้องตรวจสถานะบันทึกสำเร็จก่อนปิดงาน
- LINE ใช้ Messaging API, Telegram ใช้ bot token/chat ID และ Chatbot ใช้ HTTPS endpoint/token การแจ้งเตือนเปิดจากตั้งค่าเมื่อมีข้อมูลช่องทางครบ เวลาส่งขึ้นกับ Apps Script trigger

เก็บรหัสผ่านจริง OAuth credentials และ token ของบริการภายนอกออกจาก repository และไฟล์ GitHub Pages ใช้การตั้งค่า backend และ Script Properties สำหรับข้อมูลเชื่อมต่อที่เป็นความลับ
