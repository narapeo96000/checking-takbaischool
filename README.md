# ระบบเช็คชื่อออนไลน์ โรงเรียนตากใบ

Web App สำหรับครูเช็คชื่อจากโทรศัพท์มือถือขณะปฏิบัติงานภาคสนาม ใช้ HTML, JavaScript แบบ OOP และ SweetAlert2 หน้าเว็บเผยแพร่ผ่าน GitHub Pages ส่วนข้อมูลและการตรวจสิทธิ์ทำงานบน Google Apps Script และ Google Sheets ชื่อโรงเรียนเริ่มต้นแก้ไขได้จากหน้าตั้งค่า

## ความสามารถ

- **หน้าหลัก**: ภาพรวมการมาเรียนประจำวันและสถิติ
- **สถิติ**: กรองตามวันที่ เดือน ห้อง ครูที่ปรึกษา และนักเรียน การค้นหารายคนต้องใช้เลขประจำตัวนักเรียน พร้อมส่งออกรายงาน PDF
- **เช็คชื่อ**: เลือกวันที่และห้อง ระบุ มา / ขาด / สาย / ลา ใส่เหตุผลรายคน มีปุ่มมาครบและล้างข้อมูล พร้อมบันทึกอัตโนมัติและพิกัดประกอบรายการ
- **รายชื่อนักเรียน**: ค้นหาและกรองห้องกับครูที่ปรึกษา
- **ตั้งค่า**: ข้อมูลโรงเรียน โลโก ผู้บริหาร ธีมสี เวลารายงาน และช่องทางแจ้งเตือน
- **เข้าสู่ระบบ**: ผู้ดูแลระบบและครูที่ปรึกษา โดย backend ตรวจสิทธิ์และบันทึกการใช้งานในชีต `logs`
- **คู่มือการใช้งาน**: เปิดอ่านได้ก่อนเข้าสู่ระบบ มีขั้นตอนใช้งานบนมือถือ คำแนะนำเรื่องการซิงก์ สถิติ PDF และปุ่มพิมพ์คู่มือ

ธีมเริ่มต้นใช้แดงเข้มและน้ำตาล ปรับสีหลักและสีรองเพิ่มเติมได้จากหน้าตั้งค่า อ่าน [คู่มือบนเว็บ](https://narapeo96000.github.io/checking-takbaischool/#guide) หรือ [คู่มือสำหรับผู้ใช้งาน](docs/USER_GUIDE.md)

โค้ดพร้อมสำหรับการนำไปติดตั้ง การเชื่อมต่อฐานข้อมูลจริงต้องให้เจ้าของ Google Sheet อนุญาต Apps Script และเผยแพร่ Web App ก่อน ดู [คู่มือติดตั้ง](docs/DEPLOYMENT.md) การเก็บ source ใน repository ไม่ได้ยืนยันว่าระบบออนไลน์หรือชีตถูกสร้างแล้ว

## เริ่มติดตั้ง

1. ตั้งการแชร์ Sheet และโฟลเดอร์รายงานเป็น “จำกัด” แล้วนำไฟล์ใน `apps-script/` ไปใส่ใน Google Apps Script ของบัญชีเจ้าของ ดูขั้นตอน [ติดตั้ง](docs/DEPLOYMENT.md)
2. เรียก `setupSystem()` เพื่อสร้างชีตและบัญชีผู้ดูแลเริ่มต้น โดยไม่ต้องสร้างหัวคอลัมน์เอง
3. เผยแพร่ Apps Script เป็น Web App และนำ URL ที่ลงท้าย `/exec` มาใส่ในหน้าตั้งค่าการเชื่อมต่อของเว็บ
4. เข้าสู่ระบบด้วยบัญชีเริ่มต้น เปลี่ยนรหัสผ่าน แล้วเพิ่มห้อง ครูที่ปรึกษา และรายชื่อนักเรียน
5. เปิด GitHub Pages ให้ใช้ GitHub Actions แล้วเผยแพร่ frontend ด้วย workflow ที่เตรียมไว้

รายละเอียดสิทธิ์ Google และการทดสอบก่อนใช้งานจริงอยู่ใน [DEPLOYMENT.md](docs/DEPLOYMENT.md) โครงสร้างชีตและหัวคอลัมน์อยู่ใน [DATABASE.md](docs/DATABASE.md)

## โครงสร้าง

```text
index.html                 หน้าเริ่มต้น
config.js                  ค่าสาธารณะของ frontend
assets/                    JavaScript, CSS และไฟล์สาธารณะ
apps-script/               Google Apps Script, bridge และ manifest
docs/                      คู่มือติดตั้งและฐานข้อมูล
.github/workflows/pages.yml เผยแพร่เฉพาะ frontend
```

อย่าใส่รหัสผ่าน รหัส session, LINE/Telegram/Chatbot token หรือรายชื่อนักเรียนจริงใน repository หรือไฟล์สาธารณะของ GitHub Pages ตั้งค่าความลับผ่านผู้ดูแลระบบบน backend เท่านั้น

## ทดลองหน้าเว็บในเครื่อง

เปิดผ่าน HTTP server เพราะหน้าเว็บใช้ ES modules เมื่อมี Node.js ใช้:

```powershell
npm start
```

จากนั้นเปิด `http://127.0.0.1:4173` การทดลองหน้าเว็บอย่างเดียวไม่สร้างชีตในบัญชี Google และไม่ยืนยันการเชื่อมต่อ Apps Script

โหมดข้อมูลตัวอย่างใช้ข้อมูลสมมุติในหน่วยความจำและไม่เขียนลง Google Sheet ปุ่ม PDF ในโหมดนี้ใช้หน้าต่างพิมพ์ของเบราว์เซอร์ รายงาน PDF จริงต้องเชื่อมต่อ backend และเข้าสู่ระบบก่อน

## การทำงานภาคสนาม

อนุญาตพิกัดในเบราว์เซอร์ และใช้ HTTPS เมื่อเข้าผ่านมือถือ พิกัดมาจากอุปกรณ์ผู้ใช้และอาจคลาดเคลื่อนในอาคาร ระบบเก็บค่าความแม่นยำและเหตุที่เก็บไม่ได้เพื่อใช้ตรวจสอบย้อนหลัง พิกัดนี้ไม่ใช่หลักฐานรับรองการอยู่ในพื้นที่

เมื่อเครือข่ายขัดข้อง รายการเช็คชื่อที่รอส่งเก็บในเครื่องเดิมเฉพาะคำขอเช็คชื่อ ระบบล้างรายการค้างที่เก่ากว่า 24 ชั่วโมงเมื่อกู้คืนรายการ การเห็นสถานะรอส่งยังไม่ถือว่าบันทึกลง Sheet สำเร็จ กลับมาออนไลน์และตรวจสถานะบันทึกก่อนปิดงาน ข้อมูลค้างมีข้อมูลนักเรียน จึงควรใช้อุปกรณ์ของผู้ได้รับสิทธิ์และจัดการรายการค้างก่อนเปลี่ยนผู้ใช้ session เก็บในหน่วยความจำ ไม่เก็บใน localStorage

PDF สร้างบน backend และเก็บใน Drive ผู้ใช้ที่ผ่านการตรวจสิทธิ์ดาวน์โหลดผ่านเว็บได้ โฟลเดอร์ต้องตั้ง General access เป็น Restricted สมาชิกที่แชร์โฟลเดอร์ไว้ยังอาจมีสิทธิ์สืบทอดมายังไฟล์

ช่องทาง LINE ใช้ **Messaging API** โดยต้องมี token และผู้รับ LINE Notify ยุติบริการเมื่อ 31 มีนาคม 2568 ตาม [ประกาศ LINE Developers](https://developers.line.biz/en/news/2025/04/01/line-notify/) Telegram ต้องมี bot token และ chat ID ส่วน Chatbot ต้องมี HTTPS endpoint และ token การแจ้งเตือนปิดเริ่มต้น ให้เปิดเมื่อกรอกผู้รับและได้รับอนุญาตให้ส่งข้อความแล้ว

เวลารายงานเป็นเวลาเป้าหมาย Apps Script ใช้ trigger ซึ่งอาจทำงานช้ากว่าเวลาที่ตั้ง จึงไม่รับประกันส่งตรงนาที ดูรายละเอียดใน [คู่มือติดตั้ง](docs/DEPLOYMENT.md)
